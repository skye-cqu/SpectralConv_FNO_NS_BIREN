# Agent 开发日志规范

Agent 日志是赛题硬性提交材料，至少需要 5 段真实有效交互，并覆盖赛题列举场景中的至少 3 类：

1. 算子 kernel 设计、调试或优化；
2. 模型架构选型与超参搜索；
3. 数据预处理与特征工程；
4. 性能瓶颈分析与定位；
5. 结果分析与可视化代码生成；
6. BIREN GPU 平台适配问题排查。

## 记录原则

- 只整理真实发生的对话、操作和输出，不补写或润色成不存在的过程；
- 保留日期、工具/Agent、任务目标、关键提示、实施动作和验证证据；
- 长对话可摘要，但应附原始导出或截图路径，并保留决定性问答；
- 失败尝试同样有价值，应写清现象、证据、原因判断和下一步；
- 删除密码、token、Cookie、私有地址、个人信息及无关环境变量；
- 每条“通过”必须关联命令、commit、日志或截图；
- 记录 Agent 建议与人类最终决策的差异，避免把建议写成已执行事实。

## 推荐命名

```text
agent_logs/
├── 01_kernel_design.md
├── 02_biren_adaptation.md
├── 03_backward_debug.md
├── 04_fno_data_training.md
├── 05_performance_analysis.md
├── 06_visualization_review.md
└── evidence/
```

数量不是唯一目标；每段应体现“问题—交互—行动—证据—结论”的闭环。
新增记录应直接使用真实日期、命令和结果，不在提交目录保留空模板。

## 提交前审计

- 至少 5 段有效记录；
- 至少覆盖 3 类指定场景；
- 与 Git 历史、实验日期和日志时间一致；
- 引用文件路径真实存在；
- 没有密钥或隐私信息；
- 没有把计划、模板或合成数据冒烟写成 BIREN 正式成绩。
